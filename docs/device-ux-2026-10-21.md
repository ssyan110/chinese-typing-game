# Result clarity and tablet landscape regression

## Report and diagnosis

The supplied result shows 30 successful inputs, no incorrect submissions, three timeouts, 5,350 points and grade A. The original ratio was 30 / (30 + 0 + 3), rounded to 91%. The first chapter contains 15 distinct vocabulary entries with two successful inputs per entry. These are words, including multi-character words, rather than a count of individual Han characters.

The same result has been reproduced using the real battle engine, including the exact score, grade, stars and 15 table rows. No progress or grading migration is required.

An iPad-sized WebKit viewport at 1024 × 638 reproduced the missing scene: the stacked mobile controls left the 3D canvas just 2 pixels high (and zero in Zhuyin mode). The old landscape deck only applied below 540 pixels of height, excluding typical iPad landscape viewports.

## Changes

- Show typing accuracy independently of the existing star/rank ratio. A run with 30 correct submissions, zero incorrect submissions and three timeouts displays typing accuracy 100% and rating ratio 91%. No submitted answers displays “—”. Live statistics, results and history use consistent labels.
- Explain distinct words and successful input counts separately. Split incorrect submissions and timeouts into separate result-table columns. Preserve the 15-word first chapter, repetitions, scores and stored progress.
- Use a two-column scene/control layout on landscape touch tablets from 760 to 1400 pixels wide, including taller Safari viewports. Give wide native-keyboard layouts separate scene and input columns. Maintain document-relative arena measurements so scrolling to secondary controls cannot grow the stage repeatedly.
- Keep the existing compact treatment for extremely short software-keyboard viewports: target, time, health, feedback, pause and answer controls take priority over scenery.

## Verification scope

The automated matrix covers touch viewports 320×568, 390×844, 430×932, 568×320, 844×390, 768×1024, 1024×638, 820×1180, 1180×720, 834×1194, 1194×734, 1024×1366, 1366×900 and 800×1280; desktop viewports are 1280×720, 1440×900 and 1920×1080. Chromium and WebKit run the matrix, opening setup, course, battle, pause, result, history and settings and submitting an actual correct answer.

Additional tablet tests cover all three modes, repeated orientation changes and simulated software-keyboard heights of 400, 300, 240 and 180 pixels with visual-viewport panning. Existing phone composition, keyboard, complete chapter, learning, backup, writer-lock and journey tests remain in the release suite.

Browser emulation does not exercise a physical iPad, its native IME, Safari browser chrome or an attached hardware keyboard. These are technical browser checks, not a claim that every physical device has been tested.

Release and public-URL evidence is recorded in the local output directory after deployment.
